# Meeting Scheduler

Сервис для брони переговорок

## Что реализовано

1. Аутентификация / авторизация через login / dummylogin, register
2. Создание, листинг переговорок
3. Добавление расписания, с последующим формированием и поддержкой слотов
4. Получение свободных слотов
5. Создание брони (с возможностью получить ссылку на конференцию)
6. Получение броней, отмена брони

## Генерация слотов

Для каждой переговорки, у которой есть приложение, приложение поддерживает инвариант: созданы и доступны слоты на горизонт в 14 дней от текущего момента (другой период можно задать конфигурацией).

Поддерживается это следующим образом:
1. При создании расписания создаются слоты на промежуток [now; now+14ней]
2. Каждый час запускается работа fillhorizon.FillTail, которая для каждой комнаты с расписанием берет конец последнего слота x, и дополняет промежуток [x; now + 14 дней] слотами (идемпотентно)
3. Каждый день в час ночи и при очередном запуске приложения запускается работа fillhorizon.Repair, которая заполняет весь промежуток [now; now + 14 дней] слотами (идемпотентно)
4. При запросе на получение доступных слотов комнаты на дату, которая находится вне промежутка [now; now + 14 дней], эта дата наполняется слотами (идемпотентно), затем эти слоты идут в ответ на запрос
5. Идемпотентность операций поддерживается за счёт уникальности (room_id, slot.start_at), слоты создаются детерминированно по времени, согласно расписанию, начало слота - сдвиг k * slot.Duration (30 мин) относительно начала работы переговорки   
6. Все промежутки и тайминги можно задать конфигурацией

Выбрал данный подход для возможности быстрого чтения, так как большинство запросов будут попадать в дни с уже сформированными слотами. Тяжелая работа Repair будет запускаться во время с маленьким активом  

## Другие принятые решения

1. bookings/my возвращает только активные брони юзера
2. slots/list возвращает пустой список, если дата в прошлом, список слотов, начало которых позже текущего момента, если переданная дата - сегодняшняя

## Тесты 

Каждый юз-кейс покрыт юнит-тестами на 85%+. Весь доменный функционал так же покрыт на 90%+. Из-за большого количества сгенерированного кода (oapi-codegen, mockgen), инфраструктурного кода (http, репозитории), самих тестов, общее покрытие - 21 %

Также реализованы e2e тесты с флоу создания комнаты -> расписание -> листинг слотов -> создание брони, флоу отмены брони.
