# Meeting rooms booking service 

Сервис для брони переговорок

## Доменная область

Корпоративное бронирование переговорных комнат. Администраторы заводят переговорки и один раз задают для каждой расписание доступности (дни недели + интервал времени). По расписанию система сама нарезает 30-минутные слоты. Сотрудники смотрят свободные слоты по переговорке и дате, бронируют их на себя, отменяют свои брони; администратор видит все брони.

Ключевые правила:

- на один слот может быть только одна активная бронь;
- слоты одной переговорки не пересекаются по времени;
- нет расписания — нет слотов, переговорка недоступна;
- нельзя забронировать слот в прошлом; бронировать может только роль `user`;
- отмена брони идемпотентна;
- все даты и время хранятся и передаются в UTC.

## Стек

| Слой | Технологии |
|---|---|
| Язык | Go 1.25 |
| HTTP | REST (HTTP/1.1), роутер `go-chi/chi`, контракт в OpenAPI (`api/api.yaml`), серверный код генерируется `oapi-codegen` |
| Аутентификация | JWT (`golang-jwt/jwt`), хеширование паролей — `bcrypt` |

| Миграции | `golang-migrate` (SQL-файлы в `internal/infra/postgres/migrations`) |
| Фоновые задачи | `go-co-op/gocron` (досоздание слотов на горизонт) |
| Логирование | `log/slog` |

| Запуск | Docker, Docker Compose, манифесты Kubernetes (`k8s/`) |

Архитектура — слоистая (clean architecture): `domain` → `usecase` → `infra` / `transport`.

## Основные сущности

- **User** — пользователь: `id` (UUID), `email`, `password_hash` (опционально, для входа по паролю), `role` (`admin` / `user`), `created_at`.
- **Room** — переговорка: `id`, `name`, `description` (опц.), `capacity` (опц., > 0).
- **Schedule** — расписание доступности переговорки (не более одного на комнату, после создания не меняется): `room_id`, `days_of_week` (1–7), `start_time`, `end_time`.
- **Slot** — 30-минутный интервал в рамках переговорки, сгенерированный по расписанию и сохранённый в БД со стабильным UUID: `room_id`, `start_at`, `end_at` (UTC). Пересечение слотов одной комнаты запрещено exclusion-констрейнтом.
- **Booking** — бронь слота пользователем: `slot_id`, `user_id`, `status` (`active` / `cancelled`), `conference_link` (опц., ссылка из мок-сервиса конференций), `created_at`, `cancelled_at`. Уникальность активной брони на слот обеспечивается частичным уникальным индексом.

Связи: `Room 1—0..1 Schedule`, `Room 1—N Slot`, `Slot 1—N Booking` (из них активна максимум одна), `User 1—N Booking`.

## Что реализовано

1. Аутентификация / авторизация
2. Роли: админ, юзер 
3. Создание, получение списка переговорок
4. Добавление расписания
5. Поддержка слотов 
6. Получение свободных слотов: на дату (`/rooms/{roomId}/slots/list?date=`) и за диапазон дат до 31 дня (`/rooms/{roomId}/slots/range?from=&to=`)
7. Создание брони (с возможностью получить ссылку на конференцию)
8. Получение своих броней, отмена брони

## Генерация слотов

Для каждой переговорки, у которой есть приложение, приложение поддерживает инвариант: созданы и доступны слоты на горизонт в 14 дней от текущего момента (другой период можно задать конфигурацией).

Поддерживается это следующим образом:
1. При создании расписания создаются слоты на промежуток [now; now+14ней] (горизонт)
2. Фоновая работа, для каждой комнаты идемпотентно дополняющая горизонт слотами
3. Фоновая работа, идемпотентно заполняющая весь горизонт (запускается реже и при запусках приложения)
4. При запросе на получение доступных слотов комнаты на дату, которая находится вне горизонта, эта дата идемпотентно наполняется слотами
5. Все промежутки и тайминги можно задать конфигурацией

Выбрал данный подход для возможности быстрого чтения, так как большинство запросов будут попадать в дни с уже сформированными слотами. Тяжелая работа Repair будет запускаться во время с маленьким активом  

## Тесты 

Юз-кейс покрыты юнит-тестами на 85%+. Весь доменный функционал так же покрыт на 90%+

Также реализованы e2e тесты с флоу создания комнаты -> расписание -> листинг слотов -> создание брони, флоу отмены брони.

## Запуск

```bash
cp .env.example .env   # или просто make up — он создаст .env сам
make up                # postgres + миграции + приложение на localhost:8080
make seed              # тестовые данные (one-off контейнер из того же образа)
make down
```

Kubernetes: `k8s/` — ConfigMap (несекретный конфиг), Secret (пароли, JWT-секрет), Job для миграций, Deployment на 3 реплики с probe'ами, Service.
